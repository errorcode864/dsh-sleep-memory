# 概要后的按需逐层取证

- [配置与入口](#配置与入口)
- [返回与停止规则](#返回与停止规则)
- [会话与资源边界](#会话与资源边界)
- [验证](#验证)

C3 让模型先读取概要，信息不足时主动调用 `memory_manage expandRecall`。
每次只读取当前节点的直接来源，多个概要共享当前用户轮次的取证预算。
插件不额外调用模型判断是否展开，也不会因取证强化、唤醒或改写原始记忆。

## 配置与入口

| 配置 | 默认 | 范围与作用 |
| --- | --- | --- |
| `progressiveRecallEnabled` | `false` | 开启模型按需逐层取证 |
| `recallEvidenceMaxDepth` | `3` | `1..8`，概要为第 0 层 |
| `recallEvidenceMaxNodes` | `20` | `1..100`，当前轮次累计返回的来源条数 |
| `recallEvidenceMaxEstimatedTokens` | `2000` | `300..16000`，累计成功响应的保守 Token 估算 |

配置页可编辑上述选项，不依赖睡眠审计或再巩固开关。
开关关闭时不提供取证标识，原有 `get` 与 `traceSources` 行为保持兼容。
显式 `memory_recall` 返回有效 deep 概要后追加 `evidence`，包含 `recallId`、`rootIds` 与 `limits`。
自动注入仅对最终呈现的 deep 概要开放入口，提示中的取证用法也计入首次注入预算。
无稳定会话 ID 时不开放此入口，自动路径还需真实用户消息 ID。
若纯工具宿主没有自动注入事件，首次显式召回建立临时取证窗口。

```json
{
  "action": "expandRecall",
  "recallId": "evidence_由召回结果提供",
  "id": "smm_已呈现的概要或已发现来源"
}
```

`recallId` 必须使用当前会话实际收到的值，示例占位文本不能直接执行。
`projectId` 沿用显式参数、会话绑定、工作区和配置解析；显式跨项目召回时取证也需带相同范围。
此动作仅由 Agent 工具调用，GUI 仍使用既有只读追溯接口，不伪造会话身份。

## 返回与停止规则

返回 `items`、`hasMore`、`remaining`、`estimatedTokens` 和 `stopped`。
`items` 复用 C1 的来源预览：路径、深度、正文片段、有效性、休眠与来源类型。
每次最多返回 5 条，正文最多 300 字符，`truncated` 明确标识截断。
`items[].expandable` 表示还有下层来源且尚未达到最大深度。
`hasMore` 表示同一 ID 尚有下一页可尝试，实际请求仍受当前剩余预算约束。
模型可继续请求同一 ID 读取同层下一页，或请求已发现的子概要继续下一层。
概要足够时直接回答，预算不足或内容截断时应说明缺口，不能补造细节。

每次重新核对已发现路径上的内容版本和有效性，来源纠正、再巩固或状态变化后停止旧路径。
只沿 `consolidates` 边，严格保持起点项目范围，不将 `revises` 或联想边当成来源。
重复来源只返回首次发现路径，循环、缺失、范围不符和无效来源计数说明，不暴露被过滤目标。
证据用于解释概要，来源日期和层级可不同于最初检索概要的时间窗或层过滤。
已持久休眠的来源可作为只读证据显示，取证不会改变它的休眠状态。

| 错误码 | 含义 |
| --- | --- |
| `evidence_expired` | 其他会话、用户轮次已变、实例已重载或窗口已失效 |
| `evidence_not_offered` | 目标尚未呈现，不能跨层猜测 ID |
| `evidence_scope_changed` | 显式取证范围或当前会话默认范围已改变 |
| `evidence_changed` | 已发现路径的内容、来源或有效性发生变化 |
| `evidence_depth_limit` | 超过本轮最大来源深度 |
| `evidence_complete` | 目标直接来源已经展开 |
| `evidence_budget_exhausted` | 条数、Token 或遍历额度不足 |

范围或版本变化后在新一轮重新召回，重复同轮召回不重置已使用额度或游标。
首次响应基本信息也需预算，长路径或较小预算可能无法返回任何正文。
成功响应按完整格式化 JSON 保守估算，预留计数字段的空间，实际输出不超过计入预算的值。
错误响应不计入来源预算，也不返回来源正文；该预算不等于模型计费 Token 或全会话总消耗。
`get`、`traceSources` 和 `raw` 保留独立显式接口，不属于该累计预算。

## 会话与资源边界

每个实例最多保留 200 个会话窗口，每个窗口最多登记 50 个已呈现的概要。
单窗口总共最多检查 1000 条边，来源条数和深度采用配置上限。
窗口只在内存保存 ID、路径、范围、版本摘要、游标和计数，不保存原文或用户问题。
真实用户消息 ID 改变时新建窗口，标识相同的消息重入沿用窗口。
窗口固定保留 15 分钟，过期、容量淘汰或插件重载后需重新召回，随后建立新预算窗口。
上述额度约束单个保留窗口，不作为跨重载或无限时长的权限隔离机制。
没有多用户权限的个人 profile 仍沿用现有范围契约，取证标识不是新的身份凭据。

本实例写队列串行处理取证，避免并发请求重复使用额度。
较早轮次的审核迟到后不能为新轮次开放取证，审核拒绝或注入预算不足也不开放来源。
状态面板显示取证请求、返回条数、累计估算和拒绝原因，不展示问题或来源正文。
原有 `metrics.evidence` 继续统计成功响应实际输出估算，取证预算计数包含保守预留。

## 验证

定向测试覆盖逐层路径、只读状态、分页去重、累计预算、版本和范围变化、轮次失效及迟到审核。
真实宿主存储验收覆盖自动入口、显式入口、只读与实例重载后重新召回。
客户端契约验证配置与诊断展示，真实模型合成验证入口为 `npm run eval:evidence -- --live`。
该脚本通过 JSON 决策调用真实插件工具，不等于验证宿主原生模型工具调度。
本轮通过 73 项 smoke、232 项测试及 25 项确定性检索检查，离线标注指标与上一批一致。
文档、语法与打包检查通过；规范扫描保留 `index.js` 中 Token 说明与导出入口共现的误报。

2026-11-20 使用 `deepseek-v4.1-flash` 的首次沙箱请求均为 `fetch failed`。
沙箱外初次验收发现概要足够仍展开两层，其余场景分别超时和网络失败，实报 5116 Token。
据此调整可选递进模式下的概要提示，区分直接回答与执行前核对，保留原失败报告。
复测使用 6 次请求且三个场景均通过，服务端实报输入 6667、输出 460 Token：

| 场景 | 模型调用 | 取证行为 | 总耗时 |
| --- | --- | --- | --- |
| 概要已包含答案 | 1 | 直接回答 | 5.0 秒 |
| 两层来源才有细节 | 3 | 逐层读取后回答 | 12.4 秒 |
| 来源条数不足 | 2 | 停止并说明无法确定 | 19.4 秒 |

前后报告保存于忽略的 `tmp/c3-live-evidence*.json`，未实报的失败请求不表示没有费用。
这三个样本用于开发回归，不能据此认定模型稳定停止或代表总体准确率。
个人 profile 安装、真实项目采样和长期效果仍待后续试用。
