# 深层概要跨批次再巩固

C2 在既有睡眠审计上生成概要的新版本，每次从原始来源取材。
本批使用本地相似度与原句摘录，不调用模型生成原则，也不修改事实原文。
旧概要、各版来源和修改原因保留可查，自动递进取证属于后续 C3。

## 开启与处理范围

```yaml
sleepAuditEnabled: true
reconsolidationEnabled: true
```

`reconsolidationEnabled` 默认关闭，可在插件配置页设置，缺少审计开关时拒绝配置。
关闭该开关只停止生成后续版本，已保存的版本关系和有效性继续生效。
候选为尚未被承接且自身有效的 deep 概要，持久休眠标记会阻止再巩固。
salient 记录不加入新增证据，项目与 kind 必须与概要完全相同。

1. 沿旧概要的 `consolidates` 边取原始来源，去重并跟随事实 `replaces` 链。
2. 撤回、待复核及失效的末端来源不进入新版本，来源纠正后的末端必须有效。
3. 新证据来自本轮低强度 surface 候选，至少与一条原始来源达到 `consolidateMinSimilarity`。
4. 有新增证据或来源集合发生变化且至少保留两条证据时，才规划新版本。
5. 新版本优先摘录新增证据，其余来源按创建时间倒序排列，沿用最多 8 条首句与概要长度上限。

相似度只说明主题重叠，不证明结论等价、因果关系或用户认可。
摘要可能省略条件，完整事实仍需通过 `get` 或 `traceSources` 核对。
原概要及当前来源的触发条件合并去重，超过 4 个入口时跳过整条再巩固计划。
多个概要竞争证据时按概要创建时间、ID 顺序处理，一条证据每轮只承接一次。

## 版本与来源契约

新概要以 `consolidates` 直接关联原始来源，以 `revises` 关联上一版：

```json
{
  "target": "smm_previous_summary",
  "relation": "revises",
  "weight": 1,
  "reason": "同主题新增证据达到相似度阈值，重新整理原始来源"
}
```

旧概要的 `supersededBy` 指向新版本，来源成员同时改由新概要承接。
前后指针匹配才停用旧概要，版本关系不与事实纠正链共用 lifecycle。
旧概要的正文和来源边保留；最新版本失效不会令旧版本自动重新参与召回。
原有中间概要经承接链保持隐藏，新概要直接引用原文以避免摘要再摘要。
来源被纠正或切为待复核、失效时，当前概要立即退出有效召回。
下次睡眠可据剩余有效来源重建，不足两条时保持失效并报告跳过原因。
已移出概要的来源重新启用后独立参与召回，可在后续睡眠重新承接。

`memory_manage get` 对 deep 记录追加 `summaryVersion: {previousId, nextId, reason}`。
原文弹窗可读取前后版本及每版来源；这些操作不会强化或唤醒记忆。
`traceSources` 仍只沿来源边，不将 `revises` 版本边当成事实证据。
备份保留版本关系，导入拒绝循环、跨项目、跨类型或未闭合的有效版本关系。

## 有界规划与审计

每个概要最多处理 8 层来源、200 个遍历节点、1000 次边或纠正链检查及 100 条原始来源。
每轮最多比较 10000 对来源与新增候选，达到上限后受影响计划跳过。
缺失、循环、跨范围或类型、中间概要停用或已有后继版本均阻止整条计划。
已由其他有效概要承接的来源也会跳过，不覆盖其他概要的承接关系。
这些限制约束再巩固规划，原有全库视图和表层聚类仍有各自扫描成本。

睡眠报告追加 `reconsolidatedCount`、`reconsolidated`、`reconsolidationSkippedCount`、
`reconsolidationSkipped` 和 `reconsolidationComparisons`，报告列表沿用现有条数上限。
成功项含 `previousId`、新 `deepId`、全部 `members`、`reason` 及新增证据匹配来源和分数。
`consolidatedCount` 仍只计普通表层巩固，界面单独显示再巩固数量。
预演不落盘，没有新证据或有效来源变化时不创建重复版本。

新增概要、旧版本承接和成员变更作为同一审计计划保存，沿用准备、恢复和回滚机制。
记忆容量不足时不生成版本，审计容量不足时整批拒绝。
回滚恢复旧指针并将新概要标为失效，不执行物理删除。
后续强化、纠正或状态修改触发版本冲突，不能用旧批次覆盖。
再次生成版本使用新的 ID，已回滚版本继续作为历史记录保留。

## 验证

定向测试覆盖原始来源可达、跨批次更新、项目与类型隔离、休眠、触发上限和遍历上限。
同时覆盖来源纠正与撤回、重复睡眠、预演、容量拒绝、写入和回滚中断、重载恢复及备份导入。
客户端契约测试验证前后版本与原文读取，宿主存储验收验证重载、回滚及再次重载一致。
本轮通过 73 项 smoke、219 项测试和 25 项确定性检索检查，离线标注指标与上一批一致。
离线检索原有误召回、漏召回仍保留在报告中，本批不声称解决这些缺口。
文档及打包检查通过；规范扫描的两处 `RISK-PII-001` 为 Token 预算说明和禁止保存密钥的提示词共现误报。
本批不增加模型请求；个人 profile 安装和长期效果仍待后续试用。
