# 叙述历史备份与跨域恢复

E3 增加可选 v4 备份，包含记忆、睡眠审计、呈现与用户反馈、已保存的叙述历史。
默认仍导出 v1，已有 v1～v3 的格式与范围保持兼容。

## 导出与界面

```json
{
  "action": "export",
  "includeAudit": true,
  "includeFeedback": true,
  "includeNarratives": true
}
```

`includeNarratives: true` 要求另两个选项也为 `true`，所有选项须为布尔值。
工具和 GUI 均可导出；管理弹窗增加“下载含叙述历史的备份”按钮。
GUI 导入先选择文件并预演，确认按钮携带 `planToken`，同时显示四个域的新增数量及叙述跳过数量。

| 字段 | v4 内容 |
| --- | --- |
| `format` | `dsh-sleep-memory` |
| `version` | `4` |
| `scope` | `memory-audit-feedback-and-narratives` |
| `records`、`audits`、`feedback` | 沿用既有原文、审计和反馈契约 |
| `narratives` | 已确认及已撤回的完整叙述版本 |
| `checksum` | 对上述四个数组规范化后的 SHA-256 |

草稿、运行计数、会话绑定、调度、学习任务、profile 配置和模型凭据不包含在内。
叙述记录的模型服务 ID 与模型 ID 只是历史来源，不会重新配置目标模型。
GUI 下载和 v1～v3 文件仍限制 10 MiB；v4 文件超过 10 MiB 时改走分片导入，上限 160 MiB。

### 大文件预演（E5）

1. 在“备份与恢复”选择 v4 JSON，点击“预演导入”上传并校验。
2. 核对四个存储域的新增数，再点击“确认导入”；上传与预演不会写入本次备份的数据。
3. 上传中断或长时间未操作时重新预演，确认后的 I/O 中断则沿用下文的持久计划续写。

`backupTransfer` 只注册在 GUI Remote，模型工具仍不能导入含反馈或叙述的备份。
每个插件实例仅暂存一份备份，分片按字节偏移连续提交，每片原始内容最多 256 KiB。
宿主组装完整文件后才解析 UTF-8 JSON，并复用 v4 摘要、容量、引用和冲突校验；分片传输不等于流式解析。
上传 ID 与预演凭据绑定，重复确认复用同一次写入结果；空闲 15 分钟或插件卸载后暂存失效。
文件替换不覆盖正在处理的预演或恢复，不放宽 GUI 下载限制。

## 导入约束

v4 与 v3 一样仅允许 GUI 预演和确认导入，模型工具不能通过备份恢复伪造用户确认。
这不是备份签名或身份认证，用户应自行核对选择的文件。

所有记忆、审计、反馈与叙述先整体校验，任何一项失败都不保存恢复计划。
同 ID 同内容跳过，同 ID 异内容拒绝，包括确认与撤回状态的差异。
新增版本和目标已有版本合并后，再检查：

- 底稿存在且项目一致，仍为原始经历；不允许事实、偏好或深层概要替代底稿。
- 每段历史引文仍逐字存在于底稿。
- 每条历史只有一个起点，前序存在且属于同一记忆和项目。
- 前序确认时间严格早于后继，拒绝循环、分叉与倒序。
- 全库不超过 1000 个叙述版本，单条记忆不超过 50 个。

导入片段可以引用目标库已有的底稿和前序版本，但合并后的关系必须完整。
全量导出包含所有底稿和历史，顺序不影响导入；重复 ID 不能靠相同内容绕过。
未完成的草稿不能进入备份，撤回时间和状态须符合持久 schema。

`sourceVersion` 原样恢复，不要求等于底稿当前版本。
生命周期、来源或层级变化造成的旧叙述仍可恢复为历史；读取时重新计算 `applicable`，不会重新确认或启用。
底稿文字若已改变到引文不再成立，则拒绝恢复该版本，不猜测缺失的原文。

## 预演与中断恢复

v4 沿用 `memory_backup_state` v1，为待恢复计划增加可选 `narratives` 与 `narrativeContext`。
未完成的旧 v2、v3 恢复计划仍按原格式读取。

先保存完整恢复计划，再按记忆 → 审计 → 反馈 → 叙述写入，最后保存完成标记。
任一步 I/O 失败均透出错误，下一次普通记忆或叙述访问会先尝试恢复；重载也会继续原计划。
恢复结束前这些访问不返回半成品；失败时不会自动回滚或删除已写入记录。
审计历史和容量入口保留原有只读行为，不能将其可读视为四域恢复已完成。

`planToken` 除备份摘要与新增 ID 外，还绑定合并后的叙述历史及相关完整底稿。
中断恢复再次核对相同内容摘要；已有前序或底稿发生变化时也会阻止续写。
恢复成功后刷新已有反馈索引；叙述历史直接读取持久存储，无额外缓存需要刷新。
完成标记只保留摘要与时间，重复导入不会新增版本或让撤回版本复活。

底层没有跨域事务；本方案沿用同实例串行队列，不支持多个进程同时修改相同数据目录。
恢复后的叙述继续保护原始底稿免于物理遗忘，关闭叙述开关不影响历史读取或撤回。

## 验证与后续

定向测试覆盖格式与校验摘要、跨项目引用、逐字引文、版本链、容量、状态冲突、预演失效和六个写入阶段的故障。
客户端契约使用真实 Remote 验证 v4 下载、预演计数、确认与撤回历史恢复。
真实宿主验证新目录导入时叙述写入中断，关闭开关后重载续写，最终四域校验摘要一致。
全量 278 项测试、73 项 smoke、25 条确定性检索场景及打包检查通过，文档检查无问题。
按开发规范与接口设计 Skill 审查；`index.js` 的 Token 预算文案邻近导出描述触发既有 `RISK-PII-001`，人工核对后保留为误报。
本批不新增模型请求；浏览器视觉与长期个人项目效果未验收。

已完成[容量验证](memory-capacity.md)；E5 另用 12.79 MiB 合成文件覆盖真实宿主磁盘的确认中断与重开续写，四域摘要及撤回历史一致。
E4 的 20,000 条长记录（127.67 MiB 格式化文件）在 E5 通过内存替身的分片上传、预演、确认及四域摘要核对。
这一次的进程峰值 RSS 约 2033 MiB，包含合成数据、快照替身及重新导出，不代表生产宿主的内存开销。
客户端契约覆盖多分片上传与两步确认，未在桌面界面手工操作，也未验证 160 MiB 上限的完整磁盘恢复。
