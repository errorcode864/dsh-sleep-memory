# 实际结果驱动的激励与警示

- [启用与用户确认](#启用与用户确认)
- [召回与反例](#召回与反例)
- [持久历史与备份](#持久历史与备份)
- [验证与边界](#验证与边界)

D 在实际呈现的记忆上记录情境、做法、结果和原文证据，支持成功与失败两个方向。
用户确认与既有情绪评分分别保存，访问次数、重复召回和模型自评不算实际结果。

## 启用与用户确认

```yaml
feedbackEnabled: true
outcomeRecallEnabled: true
```

`outcomeRecallEnabled` 默认关闭，要求同时开启 `feedbackEnabled`。
关闭结果召回仅停止派生激励与警示，已有历史和证据保护保留。
开启普通反馈后即可在“原文与来源 → 召回反馈 → 实际结果与证据”记录结果。
用户选择当前版本的实际呈现，填写适用情境、具体线索、做法和结果，再读取原始证据并确认。
情境线索按完整短语匹配，使用逗号分隔，支持 1 至 8 个短语；不是任意语义推断。

结果沿用 GUI `manage` 的 `feedback` 动作，新增 `success`、`failure` 两种 signal：

```json
{
  "action": "feedback",
  "eventId": "用户操作的唯一标识",
  "exposureId": "实际呈现条目 ID",
  "signal": "success",
  "outcome": {
    "trigger": { "when": "迁移前核对", "cues": ["数据搬家"] },
    "action": "先备份并验证恢复",
    "result": "恢复演练成功",
    "evidence": {
      "memoryId": "smm_原始证据",
      "quote": "逐字引用结果原文",
      "version": "读取证据时 get 返回的 outcomeEvidenceVersion"
    }
  }
}
```

上述字段说明 GUI 契约，Agent 工具不能冒充用户调用反馈。
`eventId` 幂等追加，同 ID 同请求返回重复确认，同 ID 异内容拒绝。
目标必须仍是当时呈现的有效版本；证据必须属于目标同一项目、有效且不是 deep 概要。
引句须与原文逐字匹配，读取后版本变化须重新核对。
`when` 最多 200 字符，做法最多 200，结果最多 300，引句最多 500。
服务端记录目标与证据版本，绑定正文、来源、学习证据、情境、有效性和巩固关系。
强化次数、衰减、睡眠时间和唤醒标记不改变结果版本。

用户确认表示用户核对了结果，插件只验证原文与版本，不能证明语义支持、真实性或因果关系。
证据的 `source.confirmed` 不充当权限凭据；模型写出的资料也必须由用户核对后确认。
事实纠正、来源失效或重新复核使旧结果停止采用，不自动继承到纠正或再巩固的新版本。
状态重新启用会产生新版本，旧确认不自动复活；需要重新读取并确认。

## 召回与反例

结果候选只作用于同一呈现项目，全局记忆在甲项目确认的结果不影响乙项目。
适用情境和做法构成一组，同组同一原始证据 ID 只计最新的未撤回结果。
多个匹配组并存时采用最近确认的一组，最多展示最新成功与失败各一条证据。
这些计数表示按证据 ID 去重的确认数，不代表统计独立实验。

| 有效证据 | 提示方向 |
| --- | --- |
| 成功多于失败 | 用户确认的激励，提示可复用做法 |
| 失败多于成功 | 用户确认的警示，提醒检查风险 |
| 正反数量相同 | 正反并存，需要复核 |

结果通道的分数乘数为 `1 + 0.15 × abs(成功数 - 失败数) / 总数`，范围为 1 至 1.15。
反例使原方向的加成降低，更多反例可改变提示方向；该乘数不是可信概率。
其他既有排序因子仍独立计算，结果通道不改写持久 strength、valence 或 arousal。
失败也可提升风险提醒的可见度，不会永久压低整个任务类别。

只有命中具体情境才补充候选，项目、时间、层级、有效性及精确实体冲突继续生效。
做法、结果和完整引句也检查精确实体冲突，不能靠情境绕过版本或参数限制。
相关性审核可见结果与证据，审核缓存绑定这部分输入。
审核等待期间发生撤回或结果变化时，呈现前丢弃旧候选并记录 `outcome-changed`。
整个结果提示计入原注入预算，放不下时不注入、不强化、不唤醒。
开启休眠时结果情境可按既有规则唤醒记忆，仍经过审核、范围和审计流程。

撤回使用既有 `retract` 信号，明确指定同一次呈现的结果事件 ID。
撤回保留历史；撤回较新的同证据确认后，较早且仍有效的确认可以重新参与。
普通“有用、无关、错误、过时”反馈与结果反馈各自保留，不互相覆盖。
界面每次呈现展示最近 5 条未撤回结果，撤回后可继续看到更早结果。

## 持久历史与备份

结果保存在既有 `memory_feedback` v1 域，新增字段为可选扩展，旧记录保持兼容。
结果历史引用的目标和原始证据不会进入自动或手动的物理遗忘。
撤回或关闭功能后仍保留原文，可通过有效性管理停用，不破坏历史恢复关系。

默认导出 v1 仍只含记忆，`includeAudit:true` 仍导出 v2。
额外指定 `includeFeedback:true` 导出 v3，界面对应“下载含用户反馈的备份”：

```json
{ "action": "export", "includeAudit": true, "includeFeedback": true }
```

v3 的 `scope` 为 `memory-audit-and-feedback`，内容为 `records`、`audits`、`feedback`。
校验摘要覆盖三部分，包含实际呈现、普通反馈、结果证据和撤回事件。
导入先预演，再提交 `planToken`；同 ID 异内容、重复反馈顺序、跨项目证据和断裂撤回关系拒绝。
v3 仅允许用户通过管理面板预演并确认导入，模型工具不能借备份伪造用户确认。
不同实例的事件顺序冲突会拒绝合并，可在空库恢复，不自动猜测先后关系。
旧普通反馈允许保留已物理遗忘目标的历史呈现，但结果事件必须仍可找到目标和证据原文。

恢复计划先持久化，再依次写入记忆、审计与反馈；部分写入中断后重载继续完成。
反馈索引完成恢复后刷新，普通召回不会使用恢复前的旧结果。
v3 不含会话绑定、调度、学习任务、插件配置或模型凭据，不是完整 profile 迁移。

## 验证与边界

本轮通过 73 项 smoke、247 项测试和真实宿主存储验收。
覆盖正反方向、同证据去重、反例抵消、撤回恢复、原文与版本、项目隔离、审核等待及缓存变化。
同时验证界面确认与撤回、v3 预演、篡改拒绝、中断恢复、重载和原文遗忘保护。
25 项确定性检索检查通过，关闭新功能时离线标注指标与上一批一致。
本批没有新增模型调用，真实模型判断效果及长期使用仍待试用。
规范扫描的两处 `RISK-PII-001` 是 Token 预算说明和禁止保存密钥提示词的共现误报，已人工核对。
