# 本地检索与学习闭环

## 已确认约束

用户要求不外接嵌入模型，因此第 5–7 阶段不引入 Embedding Provider、向量服务、模型下载或新的 npm 依赖。
保留现有聊天模型学习、相关性审核与可选查询改写，新增本地检索本身不调用模型。
TypeScript 和 SQLite 不作为本轮前置条件。

`memory_bank` 是唯一事实来源，派生分词缓存不能改变原文、项目范围或生命周期。
已有的精确实体冲突、审核、零注入与 Token 预算必须覆盖所有新增候选。

## 第 5 阶段：本地候选规划

1. 按范围、时间、层级和生命周期过滤当前事实。
2. 复用逐条分词缓存，仅在正文、标签或关键词改变时重新分词。
3. 在当前候选集合内计算词频，避免其他项目影响相关性。
4. 用原问题检索，并按显式配置的项目术语别名增加一个补充通道。
5. 原问题的地址、端口、版本、路径和字段值冲突直接剔除。
6. 交给现有审核、摘要、条数、字符与 Token 预算流程。

`recallPlanMode` 支持 `off`、`shadow`、`local`，默认 `off`。
`shadow` 只记录候选差异，实际结果与强化仍使用原流程。
`local` 可用强词与完整实体匹配替代显式查询中的弱单字匹配，空查询浏览保留。
初始加权覆盖度门槛由 `recallMinCoverage` 控制，默认 0.35 且仅作用于本地规划。
无强匹配、无可用别名或审核全部拒绝时允许返回零条。

`recallAliases` 为最多 64 条 `{projectId, phrase, target}`。
`projectId: null` 表示仅在全局范围生效，项目别名不能泄漏到其他项目。
`phrase` 按规范化文本完整匹配，英文与技术实体保留词边界。
`target` 只用于补充候选，不替代原问题的实体约束。
词表默认空，不能把针对评测问题手填词表得到的改善称为通用语义能力。

缓存不持久化正文副本且不因强化重新分词，实例卸载即释放。
状态展示命中、重建、候选数量和最近影子差异，不保存完整查询正文。
后续需要 SQLite 时可替换缓存适配器，必须保留当前中文词边界与技术实体约束。

## 第 6 阶段：学习与反馈

### 学习

`learningPolicyMode` 支持 `current` 与 `evidence`，默认 `current`。
证据策略允许短而明确的偏好，拒绝纯继续、临时进度和无用户来源的轮次。
模型候选仍必须有真实逐字证据，助手自述不作为证据。

`memory_learning_jobs` 为独立持久域，证据策略使用稳定的会话、轮次、用户消息 ID、项目范围与策略版本生成来源键。
模型解析后先保存候选与固定记忆 ID，再写事实并完成任务。
中断后使用同一来源重放即可继续，重启时也恢复已准备的任务，不能重复新增或重新付费抽取。
无法完成的模型请求不标记完成，后续同一来源重放可以再次尝试。

已有事实比较使用同范围词面相关与近期记忆，不使用外部语义模型。
冲突候选保持 `review` 状态，不直接覆盖已有事实。

### 用户反馈

`feedbackEnabled` 默认关闭，开启后用 `memory_feedback` 独立域记录实际呈现的记忆版本与查询摘要。
每个呈现记录有服务端生成的 `exposureId`，曝光与访问次数不是正反馈。
GUI 可对实际呈现记录标注有用、无关、错误与过时，并撤回已有反馈。
事件使用 `eventId` 幂等追加，相同 ID 不同内容返回冲突。
模型工具不能自行伪造用户认可，首版反馈写入只允许 GUI 的可信用户操作。

`feedbackRankingEnabled` 默认关闭，只在开启时使用同查询、同范围、同版本的明确反馈做有限排序调整。
反馈不能让零分或实体冲突候选变成命中。
错误与过时反馈显示待复核提示，事实状态仍由已有管理预演与确认流程修改。
旧版本反馈不影响纠正后的新事实，撤回只撤销反馈本身。

## 第 7 阶段：验证与启用

先跑确定性单元测试、离线对照和真实 DSH 存储及 Remote 集成。
报告原流程、影子规划与本地规划的 Precision、Recall、误召回、漏召回、耗时和字符估算 Token。
真实模型学习质量与实际项目用户试用分别记录，不能由 Mock 测试替代。
新增功能默认关闭，试用时先在单个项目启用 `shadow` 再决定是否启用 `local` 与反馈排序。
不修改个人 profile，不自动合并或推送分支。
