# 休眠之后的开发路线

本计划承接[分层衰减、休眠与偏好召回](memory-dormancy.md)，记录后续建议和验收条件。
本轮实现以 `df5d6d6` 为基线，休眠及后续 A、B 改动已完成。
用户已确认按 A → B 实施；两批实现与定向验收已完成，结果见[召回诊断与长期表达偏好](memory-recall-preferences.md)。
完整个人 profile 安装、真实项目采样和长期效果尚未验收。

## 顺序与交付

| 批次 | 目标 | 可交付结果 |
| --- | --- | --- |
| A：召回诊断与评测 | 知道记忆为何没被用上 | 每次召回的阶段结果、偏好标注集和成本报告 |
| B：偏好适用规则 | 普通任务也能使用适用偏好 | 区分长期偏好、项目约定和当前要求的候选通道 |
| C：深层再巩固 | 将多段经验整理为可追溯原则 | 跨睡眠批次的概要更新、来源路径和审计回滚 |
| D：激励与警示 | 根据明确结果调整经验权重 | 同类情境的成功做法、风险提醒和反例修正 |
| E：回忆呈现实验 | 保留事实并允许叙述变化 | 可选的回忆视图、解释版本与原文对照 |

A、B、C1、C2、C3、D、E1、E2、E3、E5 和 E6 已实施；E4 已完成本轮容量验证，长期试用仍待实施。

各批独立交付；A 完成后进入单项目观察，后续批次复用同一套评测。
沿用不外接 Embedding、保留 JavaScript 和现有存储域的约束。

## A：召回诊断与评测（已完成）

实施前 `recentRecalls` 主要记录候选数、审核通过数和返回 ID，模型故障只有累计计数及最后原因。
本批已补齐候选未命中、审核拒绝、版本变化、去重和预算不足的逐次诊断。

1. 扩展现有指标，按候选生成、审核、呈现筛选、写入唤醒和最终返回记录数量及原因。
2. 审核拒绝与超时、调用失败分开；中断、范围变化、版本变化和容量拒绝保留独立原因。
3. 复用最近 20 次记录，不保留问题或记忆正文，不增加诊断专用模型请求。
4. 运行面板展示具体原因；诊断本身不强化、不唤醒，也不改变排序或预算。
5. 增加 36 条回归场景及 24 条按来源主题分离的留出场景，冻结标签后再调规则。
6. 沿用配置模型做有调用上限的合成评测，报告召回覆盖、误注入、失败、P50/P95 和实报 Token。

样本覆盖问法改写、普通任务应用、临时覆盖、偏好更新、引用与否定、项目与事实版本边界。
已经用于改规则的样本归入回归集，留出集失败后若参与调优则重新补充独立样本。
“始终用中文”可能适用于编程问题和绘画任务的文字回复，不能仅因任务主题不同就标成误注入。
现有编程语言负例只证明类别补充没有触发，其业务适用性应重标；保留旧报告作为当时结果。

验收要求：所有构造失败路径均有正确原因，诊断开关不改变返回结果，原预算与范围约束全部通过。
真实模型结果逐例人工核对，候选漏召回与审核漏判分别报告，不用少量样本宣布总体准确率。

实现覆盖 `index.js`、`memory-intelligence.js`、`memory-metrics.js`、`client.js`、模型评测与测试文件。
A1 诊断与面板、A2 样本与真实模型对照均已完成。

## B：偏好从问答检索走向任务适用（已完成）

分别处理“用户偏好什么”与“当前任务应应用哪些偏好”，语言、回答详略和格式优先。
长期偏好来自明确用户证据，项目代码约定限定项目；临时请求仅覆盖当前任务而不改写长期值。
明确更新长期偏好时走现有纠正与版本流程，含糊或冲突证据保留待复核。
候选识别复用学习类别与证据，逐条追加词表只用于明确术语，不能充当通用语义方案。
旧记录先派生识别，确需补充持久元数据时支持预演、审计和回滚，不批量猜测旧证据。
验收包含“平时中文 → 本次英文 → 后续恢复中文”、跨项目隔离、撤回及与新事实冲突的情况。
候选覆盖和误注入均用 A 的冻结集比较，兼顾上下文成本，达标后再扩大偏好类型。

## C：深层再巩固与有限回忆

C1 已完成只读多层来源追溯，接口、边界与 3 秒审核实测见[来源追溯验收](memory-source-tracing.md)。
审核等待与可选短期缓存已完成，具体配置与服务失败记录见[审核等待验收](memory-review-latency.md)。
C2 已实现跨批次新概要、来源纠正与失效重建、版本查看及审计恢复，见[深层再巩固](memory-reconsolidation.md)。
C3 已实现由模型按需调用的逐层取证工具，同轮累计深度、条数与 Token 预算，见[递进取证](memory-progressive-recall.md)。
D 已关联明确结果与情境、做法和原文证据，复用用户反馈、版本与撤回机制。
相同主题的新证据可生成新版本概要，保留旧版本及完整成员路径，避免反复摘要失去条件。
关联建立必须有来源依据，记录关系理由；联想不自动升级为因果或事实。
先返回概要，再按任务需要逐层取证，受深度、条数和 Token 预算共同限制。
休眠、纠正和来源失效传播复用现有契约，增加多层来源去重与循环拒绝。
验收包括原始证据可达、过时内容退出、重复睡眠幂等、部分写入恢复及批次回滚。

## D：正向激励与负向警示（已完成）

已实现 GUI 结果确认、情境候选、正反证据抵消、撤回与 v3 反馈备份，见[结果激励与警示](memory-outcome-feedback.md)。
E1 已提供原文对照，E2 已提供独立反思叙述，E3 已提供叙述版本备份恢复。

在现有 valence、arousal 和用户反馈之上关联“情境、做法、结果、证据”，支持正负经验。
成功经验在相似任务中推荐可复用做法，失败经验提示核对具体风险。
访问次数、重复召回和模型自评都不能代替用户认可或可验证结果。
连续反例、事实纠正和用户撤回允许降低旧经验权重，避免一次失败永久压制相关任务。
验收检查同类情境触发、无关任务不受影响、正负方向正确和撤回可恢复。

## E：回忆呈现与长期试用

E1 已实现年龄分档、原句片段、省略范围、底稿版本校验与界面对照，见[回忆细节收缩](memory-recollection.md)。
E1 是只读派生视图，未接管自动召回，也未保存叙述版本历史。
E2 已实现默认关闭的反思叙述、模型复核、用户确认、版本历史与撤回，见[叙述实验](memory-narrative.md)。
E3 已将解释版本纳入 v4 备份，覆盖引用校验、预演、中断重试、冲突拒绝与关闭开关后的历史读取，见[叙述备份恢复](memory-narrative-backup.md)。
E4 已跑完本轮[容量验证](memory-capacity.md)：内存替身 6 组通过，10,000 条长记录、20,000 条长记录和密集关联共 3 组超时；真实宿主磁盘的 1,000 条三组均通过。
E5 已实现 160 MiB 以内的[用户授权 v4 分片导入](memory-narrative-backup.md#大文件预演e5)，12.79 MiB 的真实宿主磁盘验收通过；模型工具仍不能确认反馈或叙述。
E6 已完成[冷分词优化与同样本容量对照](memory-capacity.md#2026-11-26-冷构建优化e6)，内存矩阵 9 组通过；不同正文收益单独报告，FTS 暂不引入。
下一步进入选定单项目的 30 轮标注，重点记录短偏好换问法召回、普通任务误注入与休眠后唤醒。
同时观察不同长正文的冷召回和密集关联重复召回，实用数据积累后再决定持久索引或存储优化。

先实现久远经历的细节收缩和按需展开，再实验叙述重构；年龄不直接决定事实可信度。
事实与来源继续作为底稿，叙述视图单独保存版本并标记推断，不覆盖日期、数值、承诺或用户偏好。
“美化”限定为可选叙述风格，不能捏造事件结果或把反思写成已发生的历史。
先积累单项目 30 个标注轮次，记录漏记、漏召回、误注入、时延、费用与休眠后的有效唤醒。
容量回归继续覆盖长记录、关联密度和重载场景，超时组不是已验收规模。
审计清理、物理遗忘、多机同步与模型权重训练不进入上述实施批次。
