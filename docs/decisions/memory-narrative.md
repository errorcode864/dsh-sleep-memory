# 可选反思叙述与独立版本

E2 为当前原始经历增加独立的反思草稿、模型复核、用户确认与版本历史。
原文始终保留；反思不进入事实表、检索排序或自动注入，确认保存也不将推断升级为事实。

## 使用方式

在插件配置开启 `narrativeEnabled`，再打开某条经历的“原文与来源 → 可选叙述实验”。
填写宿主已配置的模型服务 ID 和模型 ID，选择平实或温和风格后生成草稿。
本次操作把这一条完整底稿发送给所选模型，不自动发送其他记忆或个人 profile。

生成通常需要两次模型请求：先生成带逐字引文的反思，再独立核对有无补造历史。
完整底稿仍在弹窗上方，用户核对引文、反思与复核理由后才可确认保存。
草稿也可放弃；保存后的版本可查看前后关系并撤回，撤回不会清除历史或原文。

| 配置 | 默认值 | 范围 |
| --- | --- | --- |
| `narrativeEnabled` | `false` | 开启后才允许生成与确认 |
| `narrativeTimeoutMs` | `15000` | 每次模型请求 500 至 60000 毫秒 |

关闭开关后仍允许查看历史和撤回已有版本。
模型路由按本次表单指定，凭据由宿主管理；插件不另存 API key。

## 内容边界

只接受当前有效的原始经历；事实、明确标为偏好的记录与深层概要不能生成反思。
底稿上限 6000 字符，超过时拒绝而不截断；明显的密钥材料不发送给模型。
显著经历可以使用此入口，但年龄不会自动改变叙述风格或事实可信度。

模型只返回 1 至 3 段 `{quote, text}`：引文 2 至 500 字符，反思 2 至 400 字符。
本地校验拒绝未知字段、非逐字引文及原文中不存在的阿拉伯数字序列。
模型复核另查日期、数值、承诺、偏好、否定条件、事件结果与因果，任何拒绝或格式错误均不产生可确认草稿。
上述检查不能证明自然语言完全无误，保留人工核对与“模型推断”标记。

温和风格仅调整反思措辞，不能把失败说成成功、否定伤害或承诺未来一定成功。
生成材料中的指令只作为资料，不能获得工具权限或当前授权。

## 管理契约

这些操作仅通过 GUI Remote 的 `manage` 调用，不注册为模型工具：

| action | 必需参数 | 结果 |
| --- | --- | --- |
| `narrativeDraft` | `id`、`expectedVersion`、`requestId`、`style`、`provider`、`model` | 待确认草稿与过期时间，或已保存的 `savedId` |
| `narrativeConfirm` | `id`、`draftId` | 保存的版本 ID、是否重复确认及状态 |
| `narrativeHistory` | `id` | 分页版本、是否仍匹配当前底稿 |
| `narrativeRetract` | `id`、`versionId` | 撤回的版本 ID |

所有操作均支持 `projectId` 并沿用同项目及全局读取规则。
`expectedVersion` 来自 `get.recollectionVersion`；`style` 为 `reflective` 或 `gentle`。
`requestId` 为不超过 100 字符的非空标识，同一请求重试不重复调用成功的草稿或新增已保存版本。
同一请求标识不能换底稿、风格或模型；生成失败后可重试，每次重试仍按实际模型调用计费。
历史分页默认 `offset: 0, limit: 10`，最多每页 20 条。

草稿保存在本实例内存中，15 分钟过期，最多 20 份；重载后须重新生成未保存草稿。
同一请求不能并发生成，实例最多允许 2 个生成任务。
生成及复核在写队列外等待；完成时与确认时分别核对原文版本、有效性及上一叙述版本。
底稿或历史已变化时返回 `conflict`，不能覆盖新版本。
超时、卸载、复核拒绝和写入故障均透出错误；写入失败保留草稿供有效期内重试。

## 保存与原文关系

独立存储域为 `memory_narratives` v1；每条解释记录包含：

- 原始记忆 ID、项目与原文版本。
- 逐字引文、反思、模型复核理由及策略版本。
- 风格、模型服务 ID、模型 ID、确认时间与上一版本 ID。
- `confirmed/retracted` 状态及撤回时间。

接口中的 `inferred: true` 表示反思；`applicable` 只表示未撤回且仍匹配当前有效底稿。
旧版本不会因再次生成而被覆盖，撤回请求幂等，再次确认也不会让已撤回版本复活。
全库最多 1000 个解释版本，每条原始记忆最多 50 个，达到上限拒绝新增。
所有已保存版本，包括撤回版本，都会保护底稿不被物理遗忘；可通过有效性管理停用原文。
读取、生成和确认不强化或唤醒原始记忆。

现有 v1～v3 记忆备份不包含 `memory_narratives`，界面历史区会提示这一边界。
解释版本的备份恢复是进入长期个人试用前的下一项工作，本批不声称已提供完整 profile 迁移。

## 验证与下一步

自动测试覆盖默认关闭、工具隔离、引文与数字拒绝、模型复核、并发、版本变化、超时、卸载、草稿过期、写入失败与重载。
客户端契约使用真实 Remote 验证生成、人工确认与撤回；真实宿主存储验证确认落盘及关闭开关后重载历史。
全量 267 项测试、73 项 smoke 及 25 条确定性检索场景通过，打包包含新模块且排除临时报告和环境配置。
按开发规范与接口设计 Skill 审查；`index.js` 的 Token 预算和 `memory-intelligence.js` 的禁记密码提示触发既有 `RISK-PII-001` 误报，经人工核对保留例外。
计量沿用现有模型统计，`metrics.models.narrative` 汇总生成和复核的实报 Token、估算、失败与耗时。
`status.narrative` 额外提供本次加载的草稿生成、拒绝、确认与撤回计数，拒绝计数不含调用前的参数或范围错误。

`npm run eval:narrative` 只做预检；加 `-- --live` 才调用已配置模型，3 条合成场景最多 6 次请求。
报告保留原文、引文、反思与复核理由供人工核对；脚本不确认保存、不读取个人 profile。
2026-11-20 使用 `deepseek-v4.1-flash` 完成 3 条草稿，6 次请求实报 8093 Token，生成与复核合计每条约 27～44 秒。
评测单次时限设为 60000 毫秒；这不证明默认 15000 毫秒在当前服务上足够，界面可调整该值。
人工核对保留了失败、有限成功和上线限制，但“下次仍需验证”被解释为“未完成待办”，记录为细微语义偏移。
同模型复核接受了这处解释，因此不能用 3 条通过来宣布叙述准确率；报告保存在 `tmp/narrative-live-first.json`。
长期自然对话效果、独立审核模型对比与浏览器视觉验收仍待进行。
