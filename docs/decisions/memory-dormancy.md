# 分层衰减、休眠与偏好召回

本批以 `df5d6d6` 为基线，实施深层慢衰减、可回滚休眠和按需唤醒。
用户补充的“短语言偏好已记住但换种问法未召回”纳入同批修复。

## 配置与兼容

| 配置 | 默认 | 语义 |
| --- | --- | --- |
| `deepDecayHalfLifeDays` | `0` | 深层专用半衰期，整数 `0` 至 `3650` 天；`0` 沿用普通值 |
| `archiveDecayHalfLifeDays` | `0` | 归档专用半衰期，范围和回退规则同上 |
| `dormancyEnabled` | `false` | 开启休眠，要求同时启用 `sleepAuditEnabled` |
| `dormantAfterDays` | `90` | 休眠闲置期限，整数 `1` 至 `3650` 天 |
| `dormantStrengthLine` | `0.15` | 衰减后强度阈值，范围 `0` 至 `1` |

专用半衰期仍乘以 `1 + importance`，并使用增量衰减游标。
默认配置保持原行为；如需慢衰减，可先在独立试用范围设置深层 `56` 天、归档 `180` 天。
这些数值只是可调整的起点，尚未通过长期使用标定。

## 休眠与唤醒

睡眠时对满足闲置期限和强度阈值的当前 `deep`、`archive` 记录写入 `access.state: dormant`。
原层、正文、有效性和巩固成员关系保持不变，概要休眠不会释放旧成员进入普通召回。
`access` 保存状态、时间和原因，唤醒后保留 `lastWake` 的情境或关联来源。
休眠预演仅返回 `dormantCount`、`dormantIds` 等计划，实际修改进入睡眠审计。

普通词面检索不能直接带出休眠记录；明确情境条件或逐层可达的联想路径可以产生唤醒候选。
自动注入仍检查项目、有效性、精确实体、版本、去重、审核和预算。
中间节点未通过审核或预算时，下游节点不能独立唤醒。
通过呈现筛选后先写入审计再返回上下文，直接命中同时强化，关联唤醒只更新时间与状态。
存储中断时先恢复未完成批次，因此“已唤醒”不保证故障当轮已成功注入。

`memory_manage get` 和管理列表只读；`memory_recall fidelity:raw` 可以查找休眠原文。
`raw` 保留显式召回的强化行为，但单纯词面命中不会清除休眠标记。
唤醒批次使用 `report.operation: wake`，可通过既有预演回滚接口恢复休眠状态。
审计容量不足时拒绝唤醒写入，重载恢复与 v2 备份保留状态和路径。
关闭休眠开关恢复旧检索规则，不抹除历史标记。

## 短语言偏好漏召回修复

缺口位于候选生成：短偏好已入库，但词面差异使审核模型没有候选可审。
`contextualRecallEnabled` 开启时增加窄范围的回复语言类别匹配。
来源限于已验证用户证据的 `preference`，或显式声明用户确认的事实。
已有记录无需补写 `recallTriggers`，也能匹配“回复使用哪种语言”和“我习惯你用什么语种交流”。

临时要求、引述、工具来源、编程语言讨论和相反语言要求不进入这条补充通道。
这不改变原有词面召回结果，也不意味着能够理解任意同义句或所有用户偏好。
补充候选仍遵守原有范围、审核和预算，不直接作为当前用户指令。

## 验收与后续

- 已通过分层衰减、休眠预演、巩固成员保持、情境与关联唤醒、范围约束、回滚及中断恢复测试。
- 已在真实宿主存储验证休眠落盘、重载唤醒、再次重载及回滚休眠。
- 使用配置的 `deepseek-v4.1-flash` 完成两条合成语言偏好复测，两种问法均召回且审核通过。
- “编程语言的类型系统”负例未注入；绘画查询也未注入，但该例是否需要语言偏好仍保留人工判断。
- 默认关闭新功能时，离线评测与 `df5d6d6` 的误召回、漏召回及输出 Token 估算一致。

下一批优先扩大偏好改写语料，区分候选漏召回和审核拒绝，再决定是否扩展至表达风格与代码约定。
具体切片与验收条件见[休眠之后的开发路线](memory-next-plan.md)。
长期休眠阈值、真实项目轮次效果和大库延迟继续单独验证。
尚未实现任意语义联想、深层概要再次巩固或随记忆年龄进行生成式修饰。
