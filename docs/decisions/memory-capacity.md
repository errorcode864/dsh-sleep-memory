# 长记录与密集关联容量验证

E4 提供固定合成数据和独立子进程测试，覆盖索引、召回、重载及 v4 备份恢复。
本轮不增加索引依赖，不改召回算法，不进行模型请求或个人 profile 操作。

## 复现

在插件源码 checkout 中运行：

```sh
npm run bench:capacity -- --sizes 1000,10000,20000 --profiles short,long,dense --repeats 3 --timeout-seconds 240 --report tmp/capacity-memory-final.json
```

真实宿主模式先设置 `DSH_APP_PACKAGE` 为本机已安装的 `dsh/package.json` 路径：

```sh
npm run bench:capacity -- --backend disk --sizes 1000 --profiles short,long,dense --repeats 3 --timeout-seconds 240 --report tmp/capacity-disk.json
```

各组合在独立子进程顺序执行，默认最大堆为 3072 MiB；可用 `--heap-mib` 调整。
`--sizes` 支持 10～20000，`--repeats` 支持 1～10，每组合超时可设 5～900 秒。
超时只终止测试子进程，保留最近完成阶段及诊断；临时数据不会自动删除。
报告记录 Node、CPU、内存、Git 基线、参数、脚本 SHA-256、原始时间样本与数据校验摘要。

## 固定数据与口径

| 场景 | 每条正文 | 每条联想边 |
| --- | --- | --- |
| `short` | 160 字符 | 0 |
| `long` | 2000 字符 | 0 |
| `dense` | 600 字符 | 16 |

数据使用一个项目、固定时间、可定位的目标记录与环形同项目联想。
正文使用重复中文条件语句，不能代表长日志、多语种或大量唯一词的成本。
每组最多另带 1000 个叙述版本、200 条呈现记录及含 32 条前后快照的审计批次。
叙述包含四版本链及撤回状态，均为固定合成资料，不代表模型生成质量。

每组先测纯索引冷构建、复用构建和评分，再运行完整插件的预演、恢复、导出与召回。
召回区分首次和重复调用，断言目标命中、项目隔离、关联扩散与撤回历史不变。
内存模式使用严格 schema 与快照替身；重载包含 JSON 解析、记录校验及新实例首次读取。
磁盘模式使用宿主真实 `DomainFacility` 和 `JsonStorageBackend`，写入独立 `tmp/capacity-host-*` 目录并关闭后重开。
磁盘重开不清空操作系统页缓存，因此不冒充冷磁盘启动。

`P50/P95` 使用最近秩法并保留原始样本；只有 3 次的阶段 P95 就是最大值，不能作为总体延迟保证。
默认每组执行 3 轮恢复，每轮包含首次召回和 3 次重复召回，再重载执行同样查询；整组超时不等于单个操作超时。
内存指标包含合成备份、独立索引、严格替身、序列化对象和重载实例，不是插件独占开销。
内存重载期间原实例与新实例可能同时存活；不能据此推断宿主加载同一库的实际内存。
阶段采样堆和 RSS 可能漏掉瞬时峰值；报告额外提供子进程 `maxRSS`。
每次显式召回沿用访问强化语义，导出一致性在首次召回前验证。
睡眠聚类和模型等待不在本次容量范围内。

## E4 当时的边界

GUI 选择文件先校验实际字节数，导入和导出接口校验紧凑 JSON 大小，下载还校验格式化 JSON 的 Blob 大小，均限制 10 MiB。
测试调用 GUI 后端接口，下载边界按格式化字节数判定，不执行浏览器下载。
超限组先断言 GUI 拒绝，再使用管理工具测导出和内部可信入口测恢复；报告标为 `internal-only`。
这个测试入口不是面向用户的大文件恢复渠道，不能用内部通过声称 GUI 可用。
`maxRecords` 超限通过实际导入预演验证，拒绝后目标库必须仍为空。

首次矩阵发现大备份导出被 GUI 限制，记录在 `tmp/capacity-memory.json`。
调整测试以区分 GUI 边界和内部能力后复测，原始失败报告保留。

## 2026-11-20 实测

两套矩阵均基于 `6392816`，环境为 Windows x64、Node `v24.14.0`、AMD Ryzen AI 9 365 和约 31 GiB 内存。
每组计划 3 轮，整组限时 240 秒，子进程最大堆设置为 3072 MiB。
全量报告早于脚本指纹功能，更新后的启动器另用每组 10 条的三个场景复测通过。

### 内存替身

9 组中 6 组完成，3 组超时；原始报告为 `tmp/capacity-memory-final.json`。
耗时为 P95（毫秒，四舍五入）；超时行只统计已完成操作，不代表整组通过。

| 1,000 | 短 | 通过 | 1.75 / 2.14 | 211 | 59 | 137 |
| 1,000 | 长 | 通过 | 7.35 / 7.75 | 3,287 | 91 | 232 |
| 1,000 | 密集 | 通过 | 4.25 / 5.56 | 998 | 135 | 406 |
| 10,000 | 短 | 通过 | 9.58 / 11.57 | 3,931 | 510 | 1,178 |
| 10,000 | 长 | 冷召回阶段超时 | 62.56 / 64.55 | 33,651 | 870 | 2,731 |

| 20,000 | 短 | 通过 | 18.28 / 22.05 | 8,791 | 1,002 | 3,723 |

10,000 条短记录可走 GUI 导入接口，但格式化下载超限；10,000 条密集和 20,000 条短记录的恢复通过仅指内部测试。
三个超时组均已验证 GUI 拒绝超限导入和导出，但没有完成后续全量断言。

### 真实宿主磁盘

1,000 条的 3 组均通过 GUI 接口恢复、重开及召回验证；原始报告为 `tmp/capacity-disk.json`。
以下是 P50 / P95（毫秒，四舍五入），不含浏览器渲染时间。

| 场景 | 恢复写入 | 重开存储 | 首次召回 | 重复召回 | 重开后首次召回 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 短 | 7,840 / 8,398 | 140 / 177 | 202 / 213 | 17 / 28 | 196 / 208 |
| 长 | 8,362 / 10,817 | 150 / 233 | 2,249 / 3,457 | 40 / 68 | 2,985 / 3,545 |
| 密集 | 7,506 / 8,128 | 141 / 150 | 586 / 588 | 32 / 50 | 558 / 570 |

真实磁盘未测试 10,000 或 20,000 条；内存结果不能代替这些规模的宿主验收。
