# 第 5–7 阶段实施清单

执行基线为 `81ec60d`，用户已授权实施并要求不外接嵌入模型。
总体契约见 [本地检索与学习闭环](memory-local-learning.md)。
保留 JavaScript 与现有存储域，不增加向量服务或 npm 依赖。

## 执行顺序

| 切片 | 主要改动 | 验收与交付 |
| --- | --- | --- |
| 5A：锁定基线与接口 | 扩展 `eval.mjs`、fixtures | 区分词面能力、词表覆盖与真实模型效果 |
| 5B：分词缓存 | 新增 `memory-search-index.js` | 强化不重复分词，纠正及时更新，统计限定当前范围 |
| 5C：影子候选规划 | 新增 `memory-query-plan.js`；扩展 `runRecallCore` | 原结果与强化不变，记录候选差异 |
| 5D：本地规划注入 | 项目术语别名、强词门槛、原实体过滤 | 减少弱碎片误命中，所有通道仍受审核与预算约束 |
| 6A：学习触发与重复 | 扩展 `memory-intelligence.js`、来源键和学习评测 | 稳定短句可记，临时任务不记，重载不重复学习 |
| 6B：反馈闭环 | 新增 `memory-feedback.js` 与独立存储域；扩展 manage 和 GUI | 实际呈现可追溯，误用可反馈，过时反馈不误伤新事实 |
| 7A：真实宿主验收 | 扩展 host 集成、Remote 与独立持久域测试 | 覆盖重载、取消、学习中断和恢复 |
| 7B：项目内启用 | shadow 报告、单项目 local、成本与质量对照 | 达到门槛才扩展范围，随时 off 回到旧流程 |

优先交付 5A–5C，得到可运行的影子候选报告后再实现 5D。
5D 与 6A 分开评测，避免把检索改善和学习策略变化混成同一个实验。
6B 完成后才把反馈加入排序，不能先用访问次数代替用户认可。

## 切片工作卡

### 5A：建立可比较的评测

- 固定当前 22 条问题和基线 ref，保留两个用户案例的来源。
- 加入同义表达、困难负例与长记录条件，按会话和主题划分留出集。
- 报告候选覆盖率、审核后 Precision、最终误注入率、LLM 次数与总 Token。
- 增加学习样本格式，分别标注应记、拒记、重复和冲突。
- 完成条件：逐例可解释失败，新增配置默认关闭，基线行为不变。

### 5B：复用本地分词

- 缓存逐条正文、标签和关键词的分析结果。
- 词频只按当前已过滤集合统计。
- 强化计数变化不令缓存失效。
- 完成条件：重复查询复用缓存，纠正及时重新分析且范围不串用。

### 5C–5D：候选融合与实际注入

- 原词与当前项目显式术语表分别提供候选。
- 保留字段、版本、地址、端口与绑定值约束，联想候选也受约束。
- 本地规划要求强词匹配，保留显式空查询浏览。
- 审核和注入预算共享，不增加模型调用。
- 完成条件：shadow 不改变实际选择，local 可零条且可按 ID 追溯。

### 6A：学习与冲突控制

- 独立 `memory_learning_jobs` 域保存稳定来源键，未完成轮次不产生学习。
- 旧记忆比较检索同范围词面与近期记录。
- 候选必须有用途、范围和真实证据，冲突仍走 review。
- 测试短偏好、用户否定、工具指令、临时进度、密钥与重复。
- 完成条件：证据和恢复契约通过，真实模型漏记与费用由后续项目试用评估。

### 6B：用户反馈可恢复

- `memory_feedback` 域持久化 exposure 与追加反馈事件。
- GUI 提供有用、无关、错误与过时入口，并展示来源和适用范围。
- Remote 复用 manage 并验证 GUI 可信来源，工具不能自称用户反馈。
- 旧版本错误不能自动停用新事实，事实修改仍调用既有管理流程。
- 完成条件：重复点击、撤回、写入中断和重载后结果一致。

### 7A–7B：真实宿主验收

- 独立存储目录验证 Remote、重载与卸载。
- 模拟学习任务中断，验证固定候选 ID 与恢复。
- shadow 额外候选不得强化或改变回答，local 先限定一个项目。
- 保留完整轮次费用与漏记、误注入报告，再决定是否改变默认配置。
- 完成条件：关闭新增召回、学习和反馈可恢复当前流程，保留已提交的事实状态和有效备份。

## 前置依赖与实施边界

| 条件 | 当前状态 | 处理 |

| 真实 DSH 模型能力 | 学习与审核沿用既有接口 | 真实模型质量待项目试用验证 |

本轮预计涉及本地索引、查询规划、学习任务和反馈 4 个新模块，以及入口、学习、GUI、评测与测试。
每个切片开始前按实际接口再次列出文件和改动量，不在设计阶段给出未经验证的工期承诺。
不加入图数据库、多机同步、全库模型重写或按单次反馈自动训练模型。

## 实施验证

2026-11-17：确定性检索 25 个场景、原有 smoke 73 个场景和 Node 测试 127 项通过。
22 条基线问题的本地规划自动与显式误召回均为 0，原流程分别为 6 条与 26 条。
本地规划漏召回均为 2 条，分别缺少登录过期到 JWT 续期、持久化选型到数据库产品的词面关联。
该结果不能表述为全面提高召回率，也不能以针对问题添加词表替代真实语义评估。
两条用户问题均只召回标注相关记录，原流程和影子模式输出一致。

15 条独立订单主题样本已纳入回归，覆盖项目、版本、路径大小写与困难负例。
这些样本参与边界调整后属于回归集，后续需要新的未参与调优的留出集。
学习标注集包含 12 个触发与证据场景，真实 LLM 的抽取质量未在本轮测试。

本机 20,000 条构造短记忆的单次测试中，缓存热构建约 123 毫秒，旧版重建约 1,230 毫秒。
测试同时保留旧索引比较，因此堆变化不代表缓存独占内存，也不代表实际宿主整体延迟。
原始报告保留在 worktree 的 `tmp/phase-5-7-comparison.json`、`tmp/phase-5-7-independent.json` 与 `tmp/search-benchmark.json`。

打包预演包含新增 4 个运行模块，`tmp` 测试数据未进入发布包。
20 个修改或新增的 JavaScript 文件通过语法检查，31 个改动文件通过 UTF-8、LF 与行尾检查。
文档检查无问题，Java 规范扫描报告本轮没有 Java 改动。
实现与验证在 `design/memory-phase-5-7` 独立 worktree 完成。
用户已授权合并到主目录并开始试用，试用先采用影子规划、证据学习与反馈记录，反馈排序保持关闭。
