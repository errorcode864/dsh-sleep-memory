## 授权与范围

用户已授权修复审查发现的 6 个问题，并设计、开发产品完善。基线为
`bf934e4`，原有 smoke 为 73 个场景。本计划记录实施契约，验收结果在指南中维护。
开发仅修改本插件，不操作真实记忆、不执行删除命令。用户在开发验收后另行授权
提交并推送 `0.3.0`；部署与个人 profile 热重载仍不在本次推送范围内。

## 第一步：可靠性修复

1. 所有记忆生产者统一生成 `smm_` ID；mock 在写入和重新加载时执行真实 schema。
2. 增加可选 `lastDecayAt`，只结算增量时间；旧记录首次以 `lastAccessAt` 为基准。
   无法从旧数据恢复已经重复扣除的强度，不猜测补偿。
3. `raw` 和有时间窗的查询允许检索巩固成员；增加按 ID 取全文和分页来源追溯。
4. 工具、GUI、定时睡眠共用单飞入口，所有修改经同一实例写队列串行执行。
5. 检索与强化分离，只强化实际返回或注入的直接命中。
6. 容量检查提前到计划阶段，预演与真实执行复用相同决策。

## 第二步：记忆产品契约

- 可选 `projectId`：缺省为全局；指定项目查询默认包含该项目及全局记录；
  首轮未指定项目查询只读取全局。后续统一范围解析见下方“第四步”。
  这是个人 profile 内的检索范围，不是多用户访问控制。
- 可选 `source`：来源类型、会话 ID、消息 ID、确认标记；缺省表示来源未注明。
  自动评分仅标记为模型推断，不把情绪分数当事实可信度。
- 可选 `occurredAt` / `eventEndAt`：事件发生时间或范围；原有 `createdAt`
  时间窗保持兼容，新增 `timeField: occurredAt` 查询事件时间。
- `memory_manage get`：无副作用读取原文、来源、有效状态及分页巩固成员。
- `memory_manage correct`：仅纠正同范围的有效事实；新增带 `replaces` 的事实，
  用一次持久写入完成替代，不改写原文。包含已纠正成员的概要退出有效召回，
  其他尚有效的成员重新可检索。历史读取仍可访问旧记录。
- 事实不做模糊截断；经历仍可用梗概呈现，显著情绪不自动生成不可撤销的行为规则。

## 第三步：运行与交付

- `memory_manage export/import`：带格式版本、校验摘要的 JSON 备份；导入默认预演，
  先完整校验再写入，同 ID 同内容跳过，同 ID 异内容拒绝。底层无跨记录事务，
  I/O 中断可能部分完成，重试依靠相同 ID 去重恢复，不承诺原子导入。
- `memory_manage status` 和 GUI：本次加载以来的睡眠状态、上次结果、失败、
  下次调度时间、评分与查询扩展计数；状态不冒充跨重启持久记录。
- 首轮可选 `sleepOnStart`：启动时补跑一次，默认关闭；后续到期规则见“第四步”。
- 配置页开放项目范围、评分开关及启动补跑；管理面板提供状态及原文追溯入口。
- 增加独立回归与检索评测命令；同步 README、HANDOFF 与文档索引。

## 验收

- 原有 smoke 通过，并执行严格存储 schema。
- 6 个缺陷均有失败条件清晰的回归测试。
- 项目范围、事实纠正、事件时间、原文、备份重试及错误输入均有行为验证。
- 评测覆盖精确事实、无关问题、范围隔离、过时事实、巩固前后细节可达性。
- 不引入 npm 依赖；不接入新的模型服务；真实宿主 GUI 与多主机安装另行标明验证状态。
- dense 检索、自动冲突裁决、多用户权限和多主机实时同步留待后续有独立需求时实施。

## 第四步：已确认的产品闭环

用户确认下一阶段方案后授权开发。版本提升为 `0.3.0`，实施范围如下：

1. 统一范围优先级：显式 `projectId` → 持久会话绑定 → 宿主稳定工作区
   → 配置回退 → 全局。显式 null 不被覆盖，绑定不迁移既有记忆。
2. 有效性为 `active/review/invalid`，旧记录缺省 active；整条纠正链由根记录
   一次状态写入控制。预演返回影响 ID 与 planToken，确认时重新计算。
   概要来源失效后退出自动召回，未受影响的成员恢复独立检索。
3. 新增 `memory_runtime` v1 独立域，保存会话绑定、睡眠成功时刻和失败退避。
   原 `memory_bank` v1 不改变表结构；绑定键使用摘要适配 per-record 文件名。
4. 自动注入按会话、项目和内容版本去重；整体字符预算覆盖标题、正文、来源、
   关联说明。仅实际呈现的有效直接命中强化。
5. 显著经历可选慢速衰减与到期转待复核，默认均关闭，正负经历规则一致。
6. GUI 加入绑定、状态筛选、事实纠正、纠正链、备份文件下载与导入预演。
   沿用现有 React、Remote 与配置编辑器，无新增依赖。

状态调整属于逻辑变更，不执行真实记忆删除。物理遗忘、dense 检索、
多机器同步、自动冲突裁决与自动备份不在本阶段范围。
