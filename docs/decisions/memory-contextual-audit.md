## 睡眠审计

`sleepAuditEnabled` 默认 `false`，开启后将睡眠修改前后状态写入独立 `memory_sleep_audit` v1 域。
每批先保存固定 ID 的计划，再写记忆，最后标记完成。
状态为 `prepared/applied/rolling-back/rolled-back`。

首次访问记忆或回滚前恢复未完成的批次，关闭开关后仍执行恢复。
恢复只接受计划的前态或后态，全部核对后才写入。
中断重试跳过已经达到后态的记录，不重新生成概要。
恢复失败时记忆访问明确失败，审计历史仍可读取。
同一实例的审计与恢复串行执行，不承诺跨进程并发事务。

开启审计时暂停睡眠物理遗忘，并拒绝 `memory_manage forget`。
回滚将原记录恢复到修改前状态，新概要标记 `invalid` 且保留证据。
回滚要求批次涉及的记忆没有后续强化或修改，也不能已有新增纠正引用这些记录。
存在冲突时整批拒绝；确认使用预演的 `planToken`。

默认 v1 备份仅包含记忆；[v2 备份](memory-audit-backup.md)额外保留审计域。
审计保留完整修改证据，当前没有自动裁剪和彻底遗忘功能。
关闭开关后既有审计仍保留，因此不能声称已彻底清除历史内容。
回滚只恢复记忆内容，不改写调度成功时刻或已经记录的用户反馈。
本轮不修改已有深层衰减和概要再巩固规则。

## 情境触发

`contextualRecallEnabled` 默认 `false`。
记忆可以通过 `memory_write` 和 `memory_manage correct` 附加 `recallTriggers`。
格式为最多 4 条 `{when, cues}`，每条包含 1 至 8 个具体短语。
`when` 最长 200 字符，每个 cue 为 2 至 80 字符且包含文字。
英文、技术标识符按完整边界匹配，中文按完整短语匹配。

```json
{
  "kind": "experience",
  "content": "旧语句执行失败，应先核对目标产品的兼容清单。",
  "recallTriggers": [
    {
      "when": "准备迁移数据时回顾兼容性教训",
      "cues": ["数据搬家", "迁移脚本"]
    }
  ]
}
```

首版只匹配当前真实用户消息或显式查询，不推断未发生的工具意图。
触发只补充候选，仍受范围、时间、生命周期、精确实体冲突和最终预算约束。
自动注入继续使用已有相关性审核，用户显式关闭审核时沿用原有契约。
命中结果的 `retrieval.triggers` 返回条件和实际命中的短语。
注入正文与审核资料也携带条件，触发不构成新的操作授权。

自动学习只接受用户或工具资料中出现过的线索，拒绝含明显密钥的触发条件。
事实纠正默认继承条件，显式传空数组可清空。
巩固合并条件且去重，超过上限时保留原记忆，避免丢失召回入口。
触发条件参与内容版本，修改条件后不会沿用旧注入去重与反馈版本。

## 管理入口

记忆银行的“管理 → 睡眠审计”支持分页历史、修改详情、恢复与回滚预演。
常用配置页提供两个新增开关。
工具与 GUI 共用以下管理操作：

| action | 参数 | 结果 |
| --- | --- | --- |
| `sleepHistory` | `offset/limit`，可选 `batchId` | 历史分页；指定批次时对修改项分页 |
| `sleepRecover` | 无 | 恢复中断批次数量 |
| `sleepRollback` | `batchId`，可选 `dryRun/planToken` | 默认预演；确认后恢复 |

`sleepHistory` 默认 20 条，最多 100 条；列表省略完整修改内容。
GUI 单次详情不能超过 10 MiB，超限时使用工具缩小分页。

## 验证边界

新增测试覆盖写入中断、完成标记失败、重载恢复、回滚前恢复、后续修改冲突和物理遗忘暂停。
情境测试覆盖无共同词语召回、范围隔离、版本冲突、待审核候选、预算和巩固入口保留。
客户端契约测试通过真实 Remote 服务验证预演与确认。
宿主实际存储测试使用独立目录验证审计跨实例读取及情境召回。
原检索评测继续与基线对照，默认配置保持原检索输出。
真实模型抽取质量、个人 profile 安装和长期成本仍需按[试用指南](../guides/model-trial.md)验证。
